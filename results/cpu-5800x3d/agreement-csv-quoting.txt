Agreement CSVs of results/cpu-5800x3d (pipelines (a) and (c)): the comparison names with a comma, now quoted
================================================================================================================
The benchmarks of opencv-cpu/preprocessing/ wrote the name of the comparison without quotes although some names have a comma ("opencv_default vs scalar reference, HALF_PIXEL
sampling (<= 1e-4)"), so a reader that splits on commas saw 8 fields in those rows and 7 in the others (pipeline (c): 6 and 5). A review of the merged pull requests found it. The
benchmarks quote such names from now on (e5::csvField); the 13 files below were written before and were repaired afterwards with scripts/e5_quote_agreement_csv.py --write: the name is
in double quotes (RFC 4180) in the rows that need it and NOTHING ELSE changes (same number of lines, the same bytes except one pair of quote characters in each row listed).
These are CPU data: no timing, no number, no pass flag changes. The fields of these files are separated by a comma and a space, so a reader has to skip the space after the separator
(Python csv.reader(..., skipinitialspace=True), pandas.read_csv(..., skipinitialspace=True)) to see a quoted name as one field.

'before' is the file as committed on main (3809465); 'after' is the file as it is now. How it was checked: a second script that does not share code with the repair (it splits the old
rows from the right and the new ones with a csv reader) found in the 13 files the same fields in every row, the same lines, the same line endings and nothing but one pair of quote
characters in each of the 672 rows repaired (11 files of pipeline (a) x 60 rows, 2 files of pipeline (c) x 6 rows). 'python scripts/e5_quote_agreement_csv.py --check' on these 13 files
after the repair: exit status 0, 0 rows that need quotes, no row has more fields than its header (7 in the 11 files of pipeline (a), 5 in the 2 files of pipeline (c)). Running --write again changes
nothing.
