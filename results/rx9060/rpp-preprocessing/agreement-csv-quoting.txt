RPP agreement CSVs of results/rx9060/rpp-preprocessing (pipeline (a)): the notes with a comma, now quoted
=========================================================================================================
The agreement files of the RPP benchmark (rpp/benchmark_rpp_preprocessing.h) were written before fklb::CsvWriter quoted its text fields. In the four pipeline (a) files the last
column, `note`, has a comma in the rows of the comparison `rpp_fused_api vs fkl_fused` ("FKL samples ASYMMETRIC, RPP HALF_PIXEL"; 2 regions x 30 batches = 60 rows in each file), so a
reader that splits on commas saw 9 fields in those 240 rows and 8 in the others. The numbers and the pass flag are columns 1 to 7 and are not affected. The 4 files below were repaired
afterwards with scripts/e5_quote_agreement_csv.py --write: the note is in double quotes (RFC 4180) in the rows that need it and NOTHING ELSE changes (same number of lines, the same
bytes except one pair of quote characters in each row repaired). Before the repair the files had no CR and no double quote, and the third column of every row is `interior` or `last 2
columns and rows`, so the first two columns have no comma. The separator is a comma without a space: any csv reader reads the quoted note as one field.
'before' is the file as committed on main (3809465); 'after' is the file as it is now. A second script that does not share code with the repair (it splits the old rows on commas, the
first 7 fields and the rest as the note, and reads the new rows with a csv reader) found in the 4 files the same fields in every row, the same lines, no CR, the same final newline and
nothing but one pair of quote characters in each of the 240 rows repaired. 'python scripts/e5_quote_agreement_csv.py --check' on the 4 files after the repair: exit status 0, 0 rows that need quotes,
rows by number of fields {8: 360} in each (the header has 8). Running --write again changes nothing. The benchmarks write the notes quoted from now on (fklb::CsvWriter).
