### The first fkltests run showed 8 FAIL, and why the script was changed
The first run of the group (`compile-check/first-run-*`, script as in origin/main 042a5fc) listed the targets with the name filter `_(cu|cpp)$`: 137 targets, 129 compiled, 8 FAIL: `utest_chain_check_wrong{1,2,3,4}_{cpp,cu}`. **These 8 are not failures of the head.** They are the PR's compile-fail targets: `EXCLUDE_FROM_ALL`, each with a ctest test `<target>_rejected` that builds the target through `utests/core/execution_model/utest_chain_check/check_rejected.cmake` and passes only if the build fails, with the message of the check, and with no other error. The script built every target of its list and counted them as FAIL; their first error lines were the messages of the check: `chain_check.h:115` "the OutputType of the previous Op is not convertible to the InputType of the next Op" (wrong1 and wrong4), `:143` "Complete Read Operations as continuations are not allowed. It has to be an IncompleteReadBackOperation." (wrong2), `:195` "Fusing two batch operations of different BATCH size is not allowed." (wrong3). The filter also did not list the four `utest_chain_check_wrong{1..4}_cpu_mt` targets (their names end in `_mt`). `ctest -R '_rejected$' -j1` on that build gave 12 of 12 passed, the four `_cpu_mt` ones included.

Change (approved by the coordinator; `scripts/check_fkl_tree.sh`, `scripts/check_fkl_tree_report.py`, `scripts/check_fkl_tree_compare.py`): (1) the fkltests group lists **every target of the configured tree that compiles something** (executable or library; the CMake file API, so no name filter); (2) a target that has a ctest test `<target>_rejected` is an **expected rejection**: it is not built by `make`; its result is that of the ctest test, run after the build: `REJECTED_OK` when it passed, `REJECTED_FAIL` when it did not (a wrong chain that compiles, one that stops with another message, or one that has a second error); the exit status is 1 on FAIL, NOT_BUILT or REJECTED_FAIL; (3) the comparison script counts `REJECTED_OK` as OK. Checked before the rerun: the list of the new method at c8fcbe8 is the same 125 targets as the name filter's; at the head it is the old 137 plus exactly the four `_cpu_mt` targets (141); the failure paths of the report were tried on a toy project with a target that compiles, one that fails with another message, one with a second error and a correct one (three REJECTED_FAIL, one REJECTED_OK, exit status 1). Note that the libraries use `*_cu`/`*_cpp` names only by convention: the groups bench, cvgs and fastnpp keep their name filters (the bench list at c8fcbe8 is unchanged).

**Final run of the group with the extended script (`compile-check/fkltests-final-report.txt`): 141 targets, 129 compiled, 0 failed, 0 not built; 12 of 12 expected rejections held; exit status 0.** `fkltests-rejected.log` is the complete `ctest -V` output of the 12 tests (each says "rejected with the message of the check and no other error").
