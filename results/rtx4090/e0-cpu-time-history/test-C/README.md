# TEST C: the two real CPU-time programs built three ways at the current pins (window of 2026-11-06 17:25:00; the predictions below were written at 17:1x, BEFORE the window)

**Question.** Does a harness built with the flags an empty CMAKE_BUILD_TYPE gives (host code compiled at gcc's default -O0, assertions on) reproduce, with the CURRENT library, the shape of the 2025 CPU-time figure, while a Release build reproduces the 2026 values?
**What is run.** `benchmark_CPU_OpenCV_vs_cvGS_cu` and `benchmark_CPU_NPP_vs_FastNPP_cu`, built from the same sources (the working tree of fkl-benchmarks at HEAD; cvGPUSpeedup 6d26c65, FastNPP a1b5e245, FKL c8fcbe8; nvcc 13.4.92, g++ 15.2) in three CMake build types: `Release` (`-O3 -DNDEBUG`, what the repository uses), `None` (the flags of an EMPTY build type: no -O, no -DNDEBUG; what the 2025 cvGS CMake gave unless a build type was passed), `Debug` (`-g`, no -O, no -DNDEBUG). The flags of each build are written to `flags.txt` at the start of the window (from the generated `flags.make`). 3 rounds, the order of the builds rotated per round (Release None Debug / None Debug Release / Debug Release None), both programs per build, run as `scripts/run_e0.sh` runs them (own working directory, no arguments), pinned to cores 0-3,16-19, CUDA_VISIBLE_DEVICES=1 (the RTX 4090), the desktop session running, load logged every 5 s (`load.log`). The window is 17:25:00 to 17:40:00 at the latest (approved by the coordinator); script `window-script.sh`, console `window-console.txt`.
**The numbers it is compared with.** (a) The 2025 CPU-time figure, as read by the coordinator (accuracy about +-1 at batch 2, +-2 elsewhere, NOT data; `../host-path-candidates.md`, Test A): cvGS against OpenCV-CUDA about 12 / 56 / 84 / 100.5 / 112 at batches 2 / 12 / 22 / 32 / 42 and about 110 to 120 from batch 62 on (about 110 at 152); FastNPP against NPP about 12 / 43 / 60 / 70 / 74.5 at the same batches, about 92 at 142 and about 90 at 152. (b) The 2026 values of the Release build, from the old single runs of 2026-10-30 (`results/rtx4090/e0-cpu-time-opencv`, `e0-cpu-time-npp`) and the median of the three runs after #45 for FastNPP: cvGS 14.3 / 72.6 / 125.6 / 164.5 / 207.6 at batches 2 / 12 / 22 / 32 / 42, 273.9 at 62, 419.5 at 142, 411.5 at 152; FastNPP (run 1 after #45) 14.7 / 57.7 / 104.9 / 139.3 / 163.5, 203.9 at 62, 288.2 at 142, 287.0 at 152.

## Predictions (written before the window, 2026-11-06 17:1x)
1. **Release** reproduces the 2026 values: speedups within the run-to-run spread and the 5 % flag of the host-bound numbers of the old single runs (cvGS 14.3 ... 411.5, FastNPP 14.7 ... 287.0); the fused host time at batch 142 about 4.3 us (cvGS) and 6.3 us (FastNPP).
2. **None** (empty build type) gives speedups near the 2025 reading, if the empty build type explains the 2025 shape: cvGS about 12 to 14 at batch 2, about 56 to 75 at 12, about 84 to 125 at 22 ... and a plateau below about 175 from batch 62 on, FastNPP about 12 to 15 at batch 2, 43 to 58 at 12, 60 to 105 at 22, and about 90 (88 to 92) at batches 142 to 152. Quantitatively from Test B (`test-B/`, construction only, the same flags): the fused host time at batch 142 is the Release time plus about 5.8 us (cvGS) and 13.7 us (FastNPP) plus the part of the executor and the launch that was not measured (>= 0): cvGS at least about 10.1 us, i.e. a speedup of at most about 175 at batch 142; FastNPP at least about 20.0 us, i.e. a speedup of at most about 91. The per-crop slope of the fused host time (batch 2 to 42): cvGS about 0.06 us (Release 0.019), FastNPP about 0.12 to 0.13 us (Release 0.035); the constant at batch 2 larger by 0.25 to 0.35 us.
3. **Debug** (-g, no -O, no NDEBUG) gives what None gives (the host flags differ only by -g).
4. The **baseline columns** (OpenCV-CUDA, NPP host time per call) do not depend on the build type beyond the harness code around them: within the spread (a few percent).
**What would refute it.** None (or Debug) far above the 2025 values: cvGS above 200 at batches 142 to 152, or FastNPP above 130 there, or the None speedups within 10 % of Release at the same batch (the build type then does not change the per-crop host cost of the harness), or a None slope below 0.04 us per crop (cvGS) or 0.08 (FastNPP). In that case the 2025 shape is not explained by the build type with this library, and the remaining candidates of `../host-path-candidates.md` (the 2025 library code, the toolchain and machine) stay open. If None matches, the statement the numbers support is only: 'with the current library, a harness built with an empty CMAKE_BUILD_TYPE reproduces the shape of the 2025 figure'; it does not show how the 2025 binaries were built.
**Reporting after the window.** Per build: the fused host time and the speedup per batch size, the slope and the constant (batch 2 to 42 and 2 to 152), the run-to-run spread over the three rounds; Release against the old single runs of 2026-10-30 in the standing form (old / new / spread / exceeds / host-bound, 5 % flag); the baseline columns per build as the control.
