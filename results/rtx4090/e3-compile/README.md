# E3 results (compile only, RTX 4090 machine, nvcc 13.4.92, sm_89, one pinned core per compile)

- `e3_table.md`, `e3_table_chains.csv`, `e3_table_trees.csv`, `e3_table_staticloop.csv`: the tables, generated by `scripts/e3_table.py` from the CSVs below and `../e3-kernel-time/`.
  `param_space_bytes` is the kernel parameter space that ptxas checks against 32,764 B (0x7ffc), computed from the PTX layout of the parameters; ptxas' `cmem[0]` figure
  (`cmem0_bytes_ptxas`) is not that number (it includes reserved bytes).
- `e3_compile.csv` (variants A and B, current tree, first sweep), `e3_compile_B.csv` (variant B, to the first failure), `e3_compile_A_knee*.csv` (the knee of variant A, N = 1,005 to 1,300),
  `e3_limit_B_384[78].csv` (variant B at N = 3,847 and 3,848), `e3_patched_{A,B}.csv` (the include tree with get_arg without the tuple, a copy in the scratchpad),
  `e3_getarg_pr_A.csv` (the include tree of the local branch LTS-C++17-get-arg-no-tuple), `e3_trees_*.csv`, `e3_limit_{coarse,fine}_*.csv` (fold versus recursion, first failing N),
  `e3_staticloop_mul_add1.csv` (cvGS mul_add1, 2 to 19,902 operations). `*.log`: the console output of each sweep.
- `repro/`: the minimal reproducers without FKL (`fkl-self/compiletime/repro/param_cliff.py`): `param_cliff.csv` has one row per kernel: PTX counts (`ld.param`, `cvta.param`, `st.local`, local depot bytes) and
  cubin figures (registers, spill bytes, STL/LDL). Only the rows `getarg / library / K=1500 and 3000` have more than 20 registers (255).

## The limits found (current tree)

- Variant A (float, 4 B per operation): 17 registers / 0 spills up to N = 1,023, 255 registers from N = 1,024 (cause: `fk::get_arg`, see `fkl-self/compiletime/README.md`); N = 4,000 compiles in 675 s (13.6 GB);
  N = 6,000 did not finish within 3,600 s. With the fix: 17 registers at every N, N = 4,000 in 697 s (13.4 GB), N = 6,000 did not finish within 5,400 s. Parameter space limit (predicted, not reached): N = 8,177.
- Variant B (float3 / int3, 12 B per parameterised operation): ok to N = 3,847 (731 s, 12.8 GB, parameter space 32,752 B); N = 3,848 (32,768 B by the layout model) fails with a ptxas error (exit 255; the sweep CSV keeps only the truncated first line); the full message was captured at N = 4,000
  (`ptxas_error_B_4000.txt`): `Entry function ... uses too much parameter space (0x8508 bytes, 0x7ffc max)`. The layout model reproduces the 0x8508 exactly; the N = 3,848 failure was predicted by it and confirmed by a compile.
- Older trees: 1f33224 first fails at N = 248, 07b2cb3^ and 07b2cb3 at N = 245: `cannot deduce the return type of function "fk::get<Index, ...>"` at parameter_pack_utils.h(34).
