# E9 cross-library kernel (cvGPUSpeedup + FastNPP + a user operation in one `fk::executeOperations`)

Program `e9_cross_library.cu` (target `e9_cross_library_cu`); design, predictions and what the demonstration does and does not show are in its header comment. Four kernels: M1, M2 (mixed), R1 (all cvGS), R2 (all FastNPP), the same user gamma in all.

- **Listing:** lines 241-248 of `e9_cross_library.cu` (the call in the lambda `listing`), a comment on each line names the origin of the operation.
- **Prediction (2) was false** (dated note in the header): M and R differ by 8 to 16 SASS lines (M1 34 registers / 552 lines, R1 32 / 544, M2 33 / 544, R2 32 / 560; stack, shared, local 0) because the swap and the constant arithmetic are different FKL types in the two wrappers. The SASS comparison is a size comparison, not an identity test, and the time comparison M against R contains that difference as well.
- **Friction in the first draft** (an ambiguous `Gamma::build`) was a mistake of the program, not a finding about the libraries.
- **Short listing (for the paper, compiled and compared):** user op `short_listing::Gamma`, lines 70-76 (7 lines, block 68-78); call, lines 254-261 (8 lines, in the block 250-263); its output is compared with M1 in the window (`M1shortlisting_vs_M1`). Its kernel has 34 registers / 552 SASS lines, like M1.
- **The four facts of the window, in this order:** (a) each mixed kernel is ONE launch (kernel nodes of one call captured in a CUDA graph, `e9_timing.csv` column `kernels_per_call`; nsys as cross-check); (b) each mixed kernel's output is bit-identical to the single-library kernel that shares its resize (M1 with R1, M2 with R2): function `compare()` in `e9_cross_library.cu` (memcmp of the 4-byte bit pattern of every output float, plus the NaN count of both outputs; the output is pre-filled with the NaN pattern 0xff so an unwritten element shows), rows in `e9_agreement.csv`; (c) the time of each mixed kernel against its single-library kernel, 3 runs with rotated order, with the run-to-run spread (`e9_timing.csv`); (d) registers and SASS lines from the final binary of the window (compile-time values: 34 / 552 against 32 / 544, and 33 / 544 against 32 / 560; state if they changed). No unfused count is taken.
- Results (bit-exact check, kernel counts, times) come from the single window after FastNPP #45 is merged and the pin is moved; none exist yet.
